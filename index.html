Flow & Recovery Guide

How to move through the L&D Playbook Skill — and how to redirect it when it drifts. For designers and stakeholders.
Breeze University
Learning & Development

1The Flow — start to finish

One project, six blocks. The skill guides you through the flow one question at a time. Stakeholders enter at the start (as the requester) and again at the end (as the recipient of the launch). Designers move through every block.

Open
Designer
  • State what you need in plain English
  • Share any existing content (docs, prior training, SOPs, prior decks)
  • Skill picks the right Entry Point
ALIGN
Designer + Stakeholder
  • Problem framing (Q1-Q7)
  • Audience analysis
  • HPT cause analysis
  • Risk tier confirmed
  • Gate: ALIGN docket to Core Team
DESIGN
Designer
  • Learner Story
  • Design Strategy Canvas
  • Bloom's objectives → capability
  • Phillips V-Model measurement
  • Gate: Blueprint + Outline + Facilitator Guide
BUILD
Designer
  • Artifact generated (SCORM, deck, job aid)
  • Fidelity check + 5-dimension QA
  • SCORM Cloud test before Workday
  • Calibration doc if regulated
  • Gate: Build Tracker
LAUNCH
Designer + Stakeholder
  • Deployment plan
  • Communication rollout
  • L1 & L2 measurement activated
  • Early adoption monitored 2 weeks
  • Gate: Launch Summary
05-DELIVERY
Assembled record
  • Facilitator delivery package
  • Calibration audit doc
  • Project Summary
  • Ready for any auditor, facilitator, or leader to pick up

2You know the skill is working when…

These are the signals of a healthy session. If several are missing, the skill has drifted — move to Section 3.

In ALIGN

Diagnosis before design

  • Asks about content documents first
  • Walks canvas one question at a time
  • Uses your language, then reframes to the real problem
  • Runs HPT cause analysis before recommending training
  • Confirms risk tier with the 3-dimension calculator
In DESIGN

Capability-driven decisions

  • Bloom's level matches the target capability
  • Learner Story shows before/during/after/proof
  • Modality chosen with alternatives considered
  • Measurement plan drafted before build
  • Speaker notes populate in Facilitator Guide
In BUILD

Standards enforced automatically

  • Bullets, cards, visuals — no walls of text
  • Object overlap check runs after each change
  • Guest / Team Member / Business Partner capitalized
  • SCORM package tests in SCORM Cloud before Workday
  • Green "LMS: Connected" badge appears on load
In LAUNCH

Impact, not just completion

  • L1 + L2 activated Day 1
  • L3 owner named and scheduled
  • Adoption watched for 2 weeks
  • Lessons learned captured for the enterprise
  • Deliverables saved to 05-DELIVERY folder

3When the skill drifts — point it back to the playbook

You don't need to memorize corrective phrases. Just tell the skill to check the playbook. It re-reads the reference and course-corrects on its own.

The universal redirect: "Check the playbook on [what it missed]." The skill re-reads the relevant reference file and fixes its output. Your job is to spot the drift. This table shows what the skill should be doing at each moment — so you can recognize when it isn't.
If the skill does this… What the skill should be doing (per the playbook)
Jumps to solutioning without cause analysis. Running the HPT Non-Training Decision framework first — asking whether the gap is knowledge/skill, process, tools, environment, or motivation — before recommending training.
Skips the opening question about existing content. Running the Session Opening Protocol — asking whether you have SOPs, prior training, regulatory docs, or a prior deck to review before starting.
Fabricates a tool, vendor, or dashboard name. Only referencing tools you've named or that are documented in the playbook. If a tool is needed, asking you rather than inventing one.
Writes prose instead of bullets, cards, or visuals. Applying the Visual Content Standard — ≤8-word headlines, ≤10-word bullets (max 5 per slide), 40-60 words per page, 30%+ whitespace, visual treatments over paragraphs.
Uses "customer," "passenger," "employee," "contractor," "vendor." Using Breeze language: Guest, Team Member, Business Partner — always capitalized. Running the QA terminology scan to catch substitutions.
Doesn't scale rigor to the tier. Matching depth to tier. LOW = fast track, abbreviated tools. MEDIUM = full tools, 2 checkpoints. HIGH = full diagnostic, 3 checkpoints, evidence for every claim.
Self-classifies LOW when safety or regulatory is involved. Applying the safety/regulatory auto-HIGH trigger — no LOW self-classification permitted when either is in play. Escalating to L&D Core Team.
Writes feedback that references option position. Writing feedback that names the concept, behavior, or claim — never "Option A" or "the first answer." Options shuffle; positions don't reinforce learning.
Generates SCORM without the SCORM Cloud test gate. Requiring a SCORM Cloud test upload before Workday — confirming the green "LMS: Connected" badge, per-question interaction data, and completion event. Screenshot to Build Tracker.
Runs a training intake for a non-training L&D artifact. Routing to Entry Point 4 — the 4-6 lightweight intake questions for executive decks, briefings, memos, and other stakeholder communications about L&D.
Gatekeeps on data you don't have. Being data-informed, not data-dependent. Tracking missing data as an assumption with a validation plan and continuing to move forward.
Frames DELIVERY as a 5th phase. Treating the lifecycle as 4 phases (ALIGN → DESIGN → BUILD → LAUNCH). DELIVERY is the assembled record in `05-DELIVERY/`, not a phase.
Starts generating an artifact without running intake. Running the Session Opening Protocol first — every artifact-generation request from a Playbook-governed directory triggers skill-first execution.

4Universal redirects — three phrases, any moment

You don't need to remember the specifics. Three phrases handle almost every drift.

The go-to
"Check the playbook on [what it missed]."
When you can't name what's wrong
"Something feels off — re-read the playbook and walk me through your reasoning."
When you want a fresh start
"Reset — re-read the playbook and re-approach this from ALIGN."

5When redirects aren't enough — escalate

If the skill repeatedly drifts, or if a project raises enterprise concerns the skill can't resolve, escalate. This is a maturity signal, not a weakness.

Escalate when:

  1. The skill repeats the same drift after 2-3 corrections in the same conversation.
  2. The skill contradicts the playbook and you can't tell which is right.
  3. A stakeholder request conflicts with Breeze standards or values and the skill isn't pushing back.
  4. Safety, regulatory, or compliance considerations are present and the skill hasn't escalated to HIGH tier.
  5. You see a pattern — the same drift across multiple projects that other designers might also hit.

How to escalate:

  1. Note the drift — copy the specific skill output or paste the conversation snippet.
  2. Email learning@flybreeze.com with the subject "Skill drift report — [what happened]".
  3. Include the project name, tier, and what you were trying to do.
  4. Continue your work using your own judgment — do not wait for a response to keep moving.

What happens with escalations:

The L&D Core Team reviews reported drifts and updates the skill's reference files or guardrails as needed. Every designer benefits from every report. You are helping build the skill by escalating — not slowing it down.
